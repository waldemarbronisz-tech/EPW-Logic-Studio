# EPW Logic Studio

A visual Function Block Diagram (FBD) editor and runtime compiler designed for the EPW OS automation platform.

## Architecture

EPW Logic Studio strictly decouples the UI layout logic from the execution runtime.

1. **Engineering UI (`logic_studio.ui`)**: Visual drag-and-drop FBD canvas. Translates graphical wires and block placements into an internal JSON-based Object Model.
2. **Project Model (`logic_studio.core`)**: Maintains `EPW_LOGIC` project schema versioning and structural integrity.
3. **Compiler (`logic_studio.compiler`)**: Generates topological execution orders. Rejects combinational loops while explicitly allowing cycles passing through `is_stateful` memory/timer blocks.
4. **Execution Engine (`logic_studio.engine`)**: A fully headless Python PLC-style runtime execution loop, decoupled from the wall clock via `TimeProvider` and decoupled from hardware by `IOProvider`.

## Features
- **Headless Runtime:** Capable of running simulation steps completely independently of PySide6/Qt context.
- **Strict Data Typing:** Prevents logic connection bridging between incompatible boolean/float/integer boundaries.
- **Versioned, Verifiable Exports:** Compiles `EPW_RUNTIME_LOGIC` with provenance metadata (`generated_at`, `generated_by`, `project_name`, `block_count`, `contains_forced_io`, `contains_disabled_blocks`) and a SHA-256 checksum, ready for ingestion by distributed EPW OS targets.
- **Hardware Agnostic Mappings:** Leverages zero-padded endpoint binding identifiers (`ELA01.DI01`, `ADA01.DO16`).
- **Analog Chain:** Project-defined analog points (`AI`/`AO` blocks, `analog.deadband`, `analog.quality`, and hysteresis/on-off delay on every comparator) — unlike DI/DO, analog points are not fixed hardware channels; they're declared per-project in Project Settings and flow through the whole `Elementy Analogowe` library from acquisition to output.
- **Fail-Safe on Stop:** Stopping the engine (or a transition to FAULT) drives every output ever written that session to its safe state (digital `False`, analog `0.0`) instead of leaving it latched at its last value.
- **Internal Signals:** A validated project registry (`project.settings["internal_bits"]`) replaces free-text tags on `virtual.input`/`virtual.output`/`internal.reg_in`/`internal.reg_out` — a typo is a compile error, not a silently-created new signal. Picked via a `SignalPickerDialog` ("Wybór sygnału", modeled on eTango Studio's "Wybór bitu dla logiki") covering physical IO, the internal registry, and the fixed system-signal catalog (`SYS.READY`, `SYS.FAULT`, `SYS.BLINK_SLOW`, ...) in one place. The compiler detects and reports internal-signal reads that lag a scan behind their writer (a "z⁻¹" marker on the canvas), a diagnostic no reference tool offers. See `ARCHITECTURE.md` §10/§11.
- **Descriptive I/O Labels:** A project-wide registry (`project.settings["io_labels"]`, edited in Project Settings → "Etykiety wejść/wyjść") assigns a human-readable label to a physical or analog address — "ELA01.DI01" becomes "Wyłącznik Q1 zamknięty" everywhere that address is shown: on the canvas block, in the signal picker's search/description column, and in every compiler/validator message. Distinct from a block's own `Comment` (which describes *that specific block's* use of a signal, not the address itself) — see `ARCHITECTURE.md` §12. Exported in `EPW_RUNTIME_LOGIC` for EPW-OS to use as its own event-register/Historian text, so the two systems never carry independently-drifting descriptions of the same signal.
- **Short Block Identifiers:** Every block gets a project-unique, human-readable id (`g12`, `i3`, `o7`, ...) the moment it's added to the project — shown at the top of the property panel and used in every compiler/validator message instead of a 36-character UUID. See `ARCHITECTURE.md` §13.
- **Signal Cross-Reference:** A read-only "Sygnały" panel, grouped as a collapsible tree by category (Fizyczne/Analogowe/Wewnętrzne/Systemowe — several can be expanded at once), lists every signal used across all four namespaces (physical DI/DO, analog points, internal bits/registers, system signals) with its readers/writers and live-flagged issues (undefined reference, multiple writers, unused, no address assigned) — rebuilt on every project edit without needing to compile. Double-click jumps to (and briefly flashes) the block on the canvas; right-click lists every reader when there's more than one. Exports the currently filtered view to a semicolon-delimited, UTF-8-BOM CSV (`Project → Eksportuj listę sygnałów...`) for as-built documentation and client sign-off. See `ARCHITECTURE.md` §14.
- **Clipboard, Alignment & Temporary Block Disable:** An in-app clipboard (Ctrl+C/X/V, Ctrl+D) copies selected blocks with the connections between them, remapping every UUID/`short_id` fresh on paste — pasting a duplicate-address output block warns on the status bar instead of silently clearing the address or blocking the paste. Eight align/distribute operations (Edit → "Wyrównaj", or the canvas context menu with 2+ blocks selected) line up or evenly space a selection in one undo step, relative to the first-selected block. A block can be temporarily disabled ("Wyłącz blok") without removing it from the schematic — excluded from execution/export, its outputs forced to a safe defined value, and rendered dimmed with a dashed strikethrough plus a compiler warning and status-bar counter so a forgotten disabled block in safety logic can't go unnoticed. See `ARCHITECTURE.md` §15.
- **Multiple ELA/ADA Devices:** The ELA/ADA module list is project-defined (Project Settings → "Urządzenia"), not fixed at one of each — a project can address `ELA02.DI05`, `ADA03.DO12`, and so on, validated and compiled exactly like the first device. Every new/migrated project still defaults to exactly one of each, unchanged from before. See `ARCHITECTURE.md` §16.
- **Obstacle-Avoiding Wire Routing:** A wire's exit/entry direction always matches the side its own pin is mounted on; the segment in between now also avoids running through another block's body, via a grid-based A* fallback around every other block on the canvas — used only for the wires whose plain path actually crosses something (mostly backward/feedback connections in a tight layout), so the common case of an already-clear wire costs exactly what it did before. See `ARCHITECTURE.md` §17.
- **Differential Undo/Redo History:** Each undo/redo entry stores only what changed relative to its neighbor (blocks matched by uuid, not list position) instead of a full duplicate snapshot of the whole project — the topmost entry on each stack is always a full state, everything older is a compact diff. A single-block edit's stored cost stays roughly constant regardless of project size (measured: ~7x smaller at 10 blocks, ~46x at 800), so undo depth no longer punishes projects for growing. See `ARCHITECTURE.md` §18.
- **Multi-Device Simulation & Diagnostics:** The Simulation panel's DI/DO grid and every internal DI/DO index mapping now follow the project's own ELA/ADA device list instead of a fixed single-device default, and the system-signal catalog generates each device's own `<dev>.ONLINE`/`<dev>.FAULT`/`<dev>.SAFE_PATH_OK` diagnostics instead of hardcoding them for the first device only — closing the two gaps `feat/multi-device-io` deliberately left open. See `ARCHITECTURE.md` §19.
- **Constant Block Property Validation:** `const.real`/`const.int`/`const.time` property values are validated at compile time — an unparseable value, a non-finite (`NaN`/`Infinity`) REAL, or a negative TIME duration is now a compile error instead of a silent fallback to a default (or, for a value type the old code didn't guard against, an uncaught crash). See `ARCHITECTURE.md` §20.
- **Duplicate-Address Hyperlink:** Two blocks reading the same physical/internal signal (the same DI address redrawn in another part of a large diagram, say) is a legitimate pattern, not a compile error — a block's context menu gets an "Inne bloki tego samego sygnału" submenu jumping directly to every other block sharing its exact signal reference, so an engineer can confirm at a glance that a duplicate is intentional. See `ARCHITECTURE.md` §21.
- **Fixed:** a `system.signal` block bound to a REAL-typed catalog signal (`SYS.SCAN_TIME`, `SYS.CYCLE_COUNT`, `SYS.ACCESS_LEVEL`) kept its output pin stuck at the default Boolean type immediately after opening a saved project, until the engine ran at least one scan — a project compiled/exported without ever pressing Play shipped the wrong pin type to EPW-OS, and a wire to a REAL input couldn't be made right after loading. See `ARCHITECTURE.md` §22.
- **Signal Watch Panel:** A new "Obserwowane" tab, alongside Compiler/Warnings/Errors/Runtime at canvas width (not the narrow sidebar), pins any physical, analog, internal, or system signal for continuous monitoring during simulation, independent of canvas/library selection — picked via the same `SignalPickerDialog` every `Address`/`Bit`/`Sygnał` property already uses. Every column is individually resizable. Each row shows a live value and a small procedurally-drawn trend strip; double-clicking it opens an enlarged, non-modal trend window with a selectable time range (10 s to 4 h), axis labels, a manual Y-axis rescale for analog signals, and a scrollbar to pause and scroll back through recorded history without interrupting the simulation. Every recorded run is saved as part of the project file itself — closing and reopening `.epwlogic` restores the same history, no separate log file or manual export needed. See `ARCHITECTURE.md` §23.
- **Macro Blocks:** Select any subgraph on the canvas and "Utwórz makroblok..." (block context menu) collapses it into a single, named, reusable block type — its external wiring is reconnected onto the new instance's own boundary pins automatically, one undo entry. Compiles transparently: `Compiler.compile()` flattens every macro instance back into its own definition's blocks before validation/graph-building/export run, so none of the compiler pipeline or `EPW_RUNTIME_LOGIC` itself ever needs to know macros exist — nesting a macro inside another macro works too. A placed instance renders with its own accent-colored shape on the canvas, and shows up in its own "Makrobloki" section of the Library panel (drag-and-drop or double-click to place another instance, search by name). Double-click a placed instance to step "into" it like a sub-canvas — a breadcrumb trail above the canvas ("Główny › MojMakro") tracks where you are and lets you jump back out; edits made inside are committed back into that macro's own definition the moment you leave. Saving, compiling/running, and undo/redo all normalize back to the top-level project first if you're mid-edit inside one. A macro's own exposed inputs/outputs can be edited too, from right there inside its own edit view — right-click an internal block to expose one of its pins as a new boundary pin, or open "Piny makrobloku..." (next to the breadcrumb) to remove one — every placed instance of that macro anywhere in the project is resynced immediately, keeping each surviving pin's own wiring intact. Share a macro between projects (or with a colleague) by right-clicking it in the Library panel's "Makrobloki" section and exporting it to a standalone `.epwmacro` file — bundled with every OTHER macro it depends on, so a nested hierarchy always travels together; "Importuj makroblok..." pulls one back in under a fresh id, never colliding with anything already there. See `ARCHITECTURE.md` §24.
- **Project Version Diff:** "Porównaj z zapisanym plikiem..." / "Porównaj dwa projekty..." (File menu) show a human-readable summary of what changed between two `.epwlogic` states — blocks added/removed, and for a changed block, exactly which property/pin connection/setting changed and its old and new value, with a plain move-on-the-canvas kept visually separate from an actual logic change. Blocks are matched by uuid, not list position, so an insertion in the middle never makes everything after it look changed. A file saved under an older schema is transparently migrated before comparing, so a schema upgrade's own new settings keys never show up as a spurious "added" diff. See `ARCHITECTURE.md` §25.
